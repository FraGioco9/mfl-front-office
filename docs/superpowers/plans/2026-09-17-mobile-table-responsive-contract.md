# Mobile Table Responsive Contract Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make canonical player-table content respond correctly to 900/700/520/380px breakpoint crossings without rerendering rows.

**Architecture:** The canonical renderer will emit breakpoint-neutral DOM for Name, Listing, and Joined Agency. `shared-table-ui-runtime.js` will remain the responsive presentation owner, using CSS media rules for visibility and Age/marker spacing; `desktop-table-style-runtime.js` will retain the single desktop content-aware Listing overflow owner above 900px. One browser regression will resize the same rendered Database row through all breakpoints and back to desktop while asserting the row node is never replaced.

**Tech Stack:** Vanilla JavaScript DOM renderer, CSS injected by the shared table runtime, Playwright/browser regression scripts, GitHub Actions, Node.js 22.

**Spec:** `docs/superpowers/specs/2026-09-17-mobile-table-responsive-contract-design.md`

## Global Constraints

- Mobile table breakpoint: `<=900px`.
- Age/marker gap: current tablet value above 700px; `2px` at `<=700px`; `1px` at `<=380px`.
- Joined Agency compact value: `<=520px` only.
- Do not introduce a standalone Listing runtime or a second rendered-table repair owner.
- Preserve full values in DOM/accessibility; responsive presentation must not require row replacement.
- PR #1017 remains unmerged until manual approval.
