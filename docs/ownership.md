# Source ownership after issue #708

Start local development from the repository root with `npm run dev`. Build with `npm run build`. Validate with `npm run check`.

- The root `package.json` is the single application package and owns local development, build, lint, typecheck, validation, and dependencies. `predev` prepares the compatibility `public/` projection once, then `npm run dev` directly starts `next dev --webpack -p 4000`; `npm run build` finishes with `next build`; `npm run start` runs the built Next server. This matches the standard Next lifecycle used by the sibling projects. Development deliberately uses Next's Webpack bundler so Windows keeps native `node:sqlite` resolution under Node; production remains on the canonical Next build/runtime path.
- `legacy-public-assets.cjs` owns which legacy files are temporarily projected. `prepare-next-runtime.mjs` performs the deterministic projection, while `next-dev-legacy-bridge.mjs` and `dev-legacy-watch-loader.cjs` make those same files Webpack development dependencies so branch switches/resets resync `public/` and automatically refresh the open browser. The bridge is development-only migration plumbing and must shrink with the compatibility layer. `pages/api/*` contains thin Next Pages API adapters only; domain/API behavior remains owned by `api/*.js`. Do not move business logic into compatibility wrappers.
- Generated tracked artifacts still have one writer: Site Quality. The generated `public/` projection and `.next/` output are untracked build products.

- The Shared domain is source-decomposed into manifest-ordered responsibilities: `shared-foundations.js` (state/constants/DOM), `shared-session.js` (theme/account/session), `shared-routing.js` (route parsing/paths), `shared-transitions.js` (page/view transitions), `shared-page-lifecycle.js` (stable page/Table facades and base rendering), `shared-home-summary.js`, `shared-table-state.js`, `shared-toast-core.js`, `shared-personal-state.js`, `shared-data-search.js`, `shared-evaluation-lifecycle.js`, `shared-player-first-paint.js`, `shared-watchlist-actions.js`, `shared-player-display.js`, `shared-player-actions.js`, `shared-modal-lifecycle.js`, `shared-global-search.js`, `shared-wallet-row-classification.js`, `shared-html-escaping.js`, `shared-incremental-routing.js`, `shared-interaction-bindings.js`, `shared-startup-lifecycle.js`, `shared-layout-center.js`, `shared-incremental-navigation.js`, `shared-route-runtime-gate.js`, `shared-core-contracts.js`, `shared-app-startup.js`, and terminal `shared-shell-navigation.js`. These fragments are lexical source boundaries only: the manifest assembles them in order into the single `app-core-runtime.js` browser payload, so they add no browser requests. Behavioral validators must consume assembled Shared through `validate-core-sources.mjs`; direct physical-fragment reads are reserved for explicit ownership-boundary assertions. Lexical splits move TypeScript diagnostic buckets with their physical owner and may not increase aggregate debt. The assembled Shared domain retains the 355,000-byte universal ceiling; route/domain sources are split by responsibility, readability, testability, or route cost rather than arbitrary byte limits.
- `shared-incremental-routing.js` owns completed incremental-route caching and in-flight request deduplication. Completed payloads are namespaced by the published dataset generation plus linked wallet, then keyed by the canonical request; access mode remains part of that request key. Changing dataset generation or linked wallet clears completed results before reuse, and a fresh page payload adopts its `generatedAt` before being cached. Entries are promoted on read and capped at 64 by the one shared LRU-style `state.incrementalPayloadCache`; force refresh may invalidate the addressed entry. Club views and Evaluation fast selection must reuse this owner rather than create route-specific completed-result caches. Failed/aborted in-flight promises remain self-clearing through `state.incrementalRequestPromises`.
- `validate-performance-foundations.mjs` owns deterministic #923 performance enforcement. It guards cache-before-network ordering, bounded cache namespace ownership, nonblocking marketplace/entity boundaries, optional-runtime route scoping, cached browser request regressions and the opt-in timing-harness boundary. Wall-clock browser thresholds do not belong in normal Site Quality.
- `api/_database.js` owns the process-local SQLite connection, the table catalog loaded at connection-open, the one bounded prepared-statement cache used by `queryRows`/`queryOne`, and cached table-schema metadata for request-time API reads. Statement identity is exact SQL text; parameters are rebound on every execution. Table existence must reuse `tableExists()` against the loaded catalog, while table-column discovery is immutable for the lifetime of the opened snapshot and must reuse `tableColumnNames()` instead of issuing competing `sqlite_master` or `PRAGMA table_info(...)` reads.
- `html-sources/manifest.json` orders the canonical HTML fragments. Edit the route's fragment or `first-paint.html`, never generated `index.html`. Fragment boundaries preserve inline script execution order and zero-request first paint. Release/config projections are applied by `normalizeIndexDocument`. The old duplicate Player-shell migration template has been removed from the core compiler.
- `responsive-sources/manifest.json` orders canonical responsive fragments by viewport/cascade stage and UI domain. `.css.inc` files are lexical fragments, not standalone stylesheets: media blocks can cross fragment boundaries. Assembly preserves the exact original cascade bytes. New rules belong at the corresponding existing cascade position. `responsive.css` is generated for validation/source composition; production loads it inside the one flattened `styles-runtime.css` bundle, with no extra responsive stylesheet request.
- `validation/responsive-*.mjs` owns the existing responsive contracts by UI domain. `validation/assertions.mjs` shares assertion mechanics; `validation-text.mjs` shares normalized cached file reads. The domain runners retain their existing gates and failure messages.
- `scripts/database`, `scripts/marketplace`, and `scripts/email` own operational Python packages. Run entry points from the repository root with `python -m scripts.database.rebuild_database_runner`, `python -m scripts.email.progression_email_preview`, etc. Database/report paths remain rooted at the checkout, not at the relocated module directory.
- `scripts/workflows/*.sh` owns extracted workflow implementation. YAML still owns triggers, permissions, credentials, environment, working directories and artifact boundaries. Database refresh executes helpers from its `builder` checkout, including when operating on the separately checked-out published site. Scripts are invoked with `bash`; no executable-bit dependency is required.
- `tests` owns Python and scheduler regressions. Run `python -m unittest discover -v -p 'test_*.py'` and `node --test tests/*.mjs` from the repository root. Workflow contract tests follow the actual script wired into each step. Additional tests execute local configuration helpers and syntax-check every extracted shell helper without sending email or contacting production.

See `docs/architecture-guardrails.md` for the current keep/relax/remove classification of repository-level constraints.

## Why the TypeScript alias remains

The installed canonical package is `typescript@7.0.2`. Importing it returns version metadata; `createSourceFile` is undefined. The binding validator requires `createSourceFile`, syntax-kind enums and AST predicates. The installed `@typescript/typescript6` package provides those APIs, and the generated-binding regression passes with it. Substituting TypeScript 7 therefore cannot provide equivalent behavior/diagnostics. Retain the alias until the canonical package exposes a compatible compiler API, then compare both validators before removing it.

Reproduce the capability check from the repository root:

```sh
node --input-type=module -e 'const native = await import("typescript"); const legacy = (await import("@typescript/typescript6")).default; console.log({nativeVersion: native.version, nativeParser: typeof native.createSourceFile, legacyVersion: legacy.version, legacyParser: typeof legacy.createSourceFile});'
```

Generated runtime files, table-width runtime, migrations and active dependencies remain tracked. Next `public/` and `.next/` outputs are build products and are not tracked. These changes do not run a deployment.
